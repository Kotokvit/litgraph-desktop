## 1. Базовий порядок SVO

Російська та українська — SVO мови, але через розвинену флексію **порядок слів
вільний**. Усі 6 перестановок "я пошёл в магазин" граматично правильні:

| Порядок | Приклад | Призначення |
|---------|---------|-------------|
| SVO | Я пошёл в магазин | нейтральне |
| SOV | Я в магазин пошёл | акцент на дію |
| VSO | Пошёл я в магазин | оповідний зачин |
| VOS | Пошёл в магазин я | поетичне |
| OVS | В магазин я пошёл | акцент на місце |
| OSV | В магазин пошёл я | акцент на суб'єкт |

**Для LitGraph**: не можна покладатися на порядок слів для визначення
суб'єкта/об'єкта. Треба використовувати **відмінки**:
- Nominative = суб'єкт
- Accusative = прямий об'єкт
- Genitive (для одух.) = альтернатива Accusative
- Dative = непрямий об'єкт

## 2. Розпізнавання ролей через відмінки

### 2.1. Стандартна схема

```
Иван (Nom) убил (V) Петра (Acc = Gen для одух.)
└── агент ──┘    └── об'єкт ──┘
```

`KILL(Ivan, Peter, G12)` — суб'єкт у Nom, об'єкт у Accusative (для одух. =
Genitive).

### 2.2. Пасивна конструкція

```
Пётр (Nom) убит (V pass) Иваном (Inst)
└── пацієнт ──┘    └── агент ──┘
```

Та сама семантика, але ролі поміняні:
- Nom = пацієнт (того, кого вбили)
- Inst = агент (того, хто вбив)

**Для LitGraph**: при парсингу треба перевірити, чи дієслово в пасиві. Якщо так
(короткий пасивний причастник: убит, ранен, обвинён) — поміняти агент/пацієнт.

Зараз код це **не робить**. "Пётр убит Иваном" дасть `KILL(Peter, Ivan, ...)` —
помилково.

### 2.3. Безособові речення

```
Темнеет.          — без суб'єкта (безличное)
Мне холодно.      — Dative impersonal
Васю тошнит.      — Accusative impersonal
```

Для LitGraph: ці речення не генерують подій з агентом/об'єктом. Треба
фільтрувати.

## 3. Діалоги та пряма мова

### 3.1. російські схеми

| Схема | Приклад |
|-------|---------|
| Авторська репліка до | Иван сказал: "Привет." |
| Авторська репліка після | "Привет," — сказал Иван. |
| Авторська репліка всередині | "Привет, — сказал Иван, — как дела?" |
| Без атрибуції | "Привет." (з контексту зрозуміло, хто) |
| Звертанням | "Иван, привет!" (Vocative-like) |

### 3.2. українські схеми

| Схема | Приклад |
|-------|---------|
| До | Іван сказав: «Привіт». |
| Після | «Привіт, — сказав Іван. |
| Всередині | «Привіт, — сказав Іван, — як справи?» |

**Увага**: українські лапки `«...»` (крилечки), російські `«...»` або `"..."`.
У коді вже враховано `«...»` у `semantic_parser.rs`.

### 3.3. Атрибуція через дієслово мовлення

Дієслова мовлення: сказать, ответить, спросить, молвить, прошептать,
прокричать, добавить, продолжить.

Зараз код шукає `[А-ЯЁ][а-яё]+ сказал` як regex (розділ 6 `semantic_parser.rs`).
Треба розширити список дієслів мовлення.

### 3.4. Звертання (Vocative-like)

| Приклад | Аналіз |
|---------|--------|
| "Иван, иди сюда!" | "Иван" — не суб'єкт, а адресат |
| "— Марія, ти тут?" | "Марія" — адресат у кличному |

Для LitGraph: якщо слово на початку репліки + кома → це адресат, не агент.
Якщо текст український і форма в Vocative → це адресат.

## 4. Заперечення

### 4.1. Просте заперечення

| Приклад | Інтерпретація |
|---------|---------------|
| Иван не убил Петра. | `KILL` з polarity = - (не сталося) |
| Иван не убивал Петра. | недоконаний + neg → повторюваної дії не було |

**Для LitGraph**: `verb_to_action(verb_lemma, polarity, negated=true)` вже є,
але `polarity = "-"` не використовується у Reasoning для виведення
`NOT_KILL(Ivan, Peter, G12)`. Треба додати предикат `¬KILL` і правило:
`KILL(a, p, t) ∧ ¬KILL(a, p, t)` → UNSAT.

### 4.2. Множинне заперечення

"Никто никогда никому ничего не прощает" — 4 заперечні слова, одне `не`.

Для LitGraph: заперечні займенники (никто, ничто, никогда, нигде) треба
окремо маркувати — вони впливають на `polarity` предиката.

## 5. Субординація: складнопідрядні речення

### 5.1. Типи підрядних

| Тип | Сполучник | Приклад |
|------|-----------|---------|
| Часу | когда, пока, после того как | "Когда Иван вошёл, Пётр молчал." |
| Причини | потому что, ибо, так как | "Иван молчал, потому что знал секрет." |
| Наслідку | так что | "Иван знал секрет, так что молчал." |
| Умови | если, коли | "Если Иван придёт, Пётр уйдёт." |
| Цілі | чтобы, для того чтобы | "Иван пришёл, чтобы увидеть Петра." |
| Допустові | хотя, несмотря на то что | "Хотя Иван знал, он молчал." |

### 5.2. Для LitGraph

Кожен тип підрядного має семантичне значення:

| Сполучник | Предикат | Приклад виведення |
|-----------|----------|-------------------|
| когда | `BEFORE` або `CO-OCCURS` | "Когда A, B" → `BEFORE(A, B)` або `CO-OCCURS(A, B)` |
| потому что | `CAUSES` | "B, потому что A" → `CAUSES(A, B)` |
| если | гіпотеза | "Если A, то B" → `H1: A → B` |
| чтобы | `PURPOSE` | "A, чтобы B" → `PURPOSE(A, B)` |
| хотя | `CONCESSION` | "Хотя A, B" → `CONCESSION(A, B)` |

Зараз код **не розпізнає** ці зв'язки. Складнопідрядні речення парсяться як
два незалежні, що втрачає причинно-наслідкові зв'язки — основну мету LitGraph.

### 5.3. Дієприкметникові звороти

| Приклад | Розгорнуто |
|---------|------------|
| "Иван, увидевший Петра, молчал." | "Иван, который увидел Петра, молчал." |
| "Убитый Иваном Пётр лежал." | "Пётр, которого убил Иван, лежал." |

Для LitGraph: дієприкметник = стисла форма підрядного речення. Парсити як
підрядне.

## 6. Алгоритм SVO-витягу — пропозиція

### 6.1. Кроки

```
1. Сегментація речення (по . ! ?; з урахуванням скорочень)
2. Морфологічний аналіз кожного слова (лема + відмінок + число + час)
3. Пошук дієслова (якщо немає — це не SVO речення, пропустити)
4. Визначення дієслова: вид, перехідність, актив/пасив
5. Пошук суб'єкта: слово в Nominative, що узгоджується з дієсловом у числі
6. Пошук об'єкта:
   - для перехідного активного: слово в Accusative (або Genitive для одух.)
   - для пасива: слово в Instrumental (це агент, а не об'єкт)
7. Перевірка заперечення (не, никто, ничто)
8. Визначення часу (прошедшее/настоящее/будущее)
9. Формування трійки (subject, verb, object) + метадані
```

### 6.2. Обробка діалогів

```
1. Якщо рядок починається з "—" або « — це репліка
2. Шукаємо атрибуцію:
   - "сказал/ответил/спросил [А-ЯЁ][а-яё]+"
   - "[А-ЯЁ][а-яё]+ сказал/ответил/спросил"
3. Якщо атрибуція знайдена — діалог приписується цьому персонажу
4. Якщо не знайдена — використовуємо попереднього мовця ( heuristic)
```

### 6.3. Обробка підрядних

```
1. Знаходимо сполучник (когда, потому что, если, ...)
2. Розбиваємо речення на головне + підрядне
3. Парсимо кожне окремо
4. Додаємо відношення (BEFORE, CAUSES, PURPOSE, ...)
```

## 7. Метадані трійки

```rust
pub struct SvoTriple {
    pub subject: String,
    pub subject_lemma: String,
    pub subject_case: Case,        // Nominative зазвичай
    pub verb: String,
    pub verb_lemma: String,
    pub verb_aspect: Aspect,       // Perfective / Imperfective
    pub verb_voice: Voice,         // Active / Passive
    pub polarity: Polarity,        // + / -
    pub negated: bool,
    pub object: String,
    pub object_lemma: String,
    pub object_case: Case,         // Accusative зазвичай
    pub tense: Tense,              // Past / Present / Future
    pub speaker: Option<String>,   // Для діалогів
    pub sentence_id: usize,
    pub chapter_id: usize,
    pub subordinated_to: Option<usize>,  // ID головного речення, якщо підрядне
    pub subordination_type: Option<SubordinationType>,
}
```

## 8. Тести

```rust
#[test]
fn test_passive_voice_attribution() {
    let triples = parse_svo("Пётр был убит Иваном.");
    assert_eq!(triples.len(), 1);
    let t = &triples[0];
    assert_eq!(t.subject_lemma, "иван");   // Агент з Instrumental
    assert_eq!(t.object_lemma, "пётр");    // Пацієнт з Nominative
    assert_eq!(t.verb_voice, Voice::Passive);
}

#[test]
fn test_negation_marks_polarity() {
    let triples = parse_svo("Иван не убил Петра.");
    assert!(triples[0].negated);
    assert_eq!(triples[0].polarity, Polarity::Negative);
}

#[test]
fn test_dialogue_attribution_after() {
    let triples = parse_svo("\"Привет,\" — сказал Иван.");
    assert_eq!(triples[0].speaker, Some("иван".to_string()));
}

#[test]
fn test_subordinate_because() {
    let result = parse_svo("Иван молчал, потому что знал секрет.");
    assert!(result.subordination.is_some());
    let sub = result.subordination.unwrap();
    assert_eq!(sub.type_, SubordinationType::Cause);
    // Головне: "Иван молчал"
    // Підрядне: "знал секрет"
    // Зв'язок: CAUSES(знал секрет, молчал)
}
```
